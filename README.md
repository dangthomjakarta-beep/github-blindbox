# GitHub 每周盲盒

每周日北京时间 18:07，AI 自动从 GitHub Trending 筛选**真正值得关注的项目**，通常整理成 10—12 个本周项目（目标为 9 个本周新星＋3 个经典项目；极端候选不足时不少于 9 个），发到你 QQ 邮箱。

GitHub Actions 的定时任务可能延迟，18:07 是为了避开整点拥堵，不保证秒级准点；需要立即验证时可在 Actions 中手动运行。

**你不需要准备服务器。** Fork 我的仓库，配置上面的 5 个 Secret，就能让 GitHub Actions 自动抓取、筛选并发邮件。

## 数据来源：多语言覆盖，去重聚合

绝大多数 Trending 工具只看单一语言榜，视野狭窄。每周运行时，我们对 **5 个语言维度分别抓取 weekly 和 monthly**：

| 维度 | 用途 |
|------|------|
| `(全语言)` | 覆盖整体趋势 |
| `python` | 数据科学 / AI 生态 |
| `javascript` | 前端 / Node.js 生态 |
| `typescript` | 现代全栈生态 |
| `go` | 云原生 / 基础设施生态 |

weekly 与 monthly 数据按仓库去重合并；同一仓库同时出现时优先采用 weekly 热度口径，只有 monthly 数据时才采用 monthly。每条来源都保留 period，避免把日榜增量误标成周榜。

### 它和别的 Trending 产品有什么不同？

其他 GitHub Trending 相关产品（RSS 订阅、邮件简报、排行榜网站）做的事本质上就是一句话：**把热门 repo 列出来给你看**，排序方式无非是按星数或新增热度。你是那个被动接收信息的人，筛选全靠自己。

**我们做了三层过滤，不是简单的"挑几个好的"：**

**① 多源去重聚合 → 建立候选池**
通过 5 个语言维度（`python`、`javascript`、`typescript`、`go` 及全语言）分别抓取 weekly 和 monthly Trending，合并成更宽的候选池。这一步解决了单语言 Trending 视野狭窄的问题。

**② 历史去重 → 避免信息疲劳**
本周新星按 fullName 冷却至少 56 天，经典项目按 fullName 冷却至少 120 天；同时限制同一 owner 的 28 天冷却，并优先避开过去 21 天已出现的主题与相近生态。若严格避让后不足 9 个项目或不足 6 个主题，才允许近期主题回补，项目 fullName 冷却始终不放宽。

**③ 选题引擎 + 人格化 AI 撰写 → 按"人"过滤，不是按"指标"**
这是最核心的一步。程序先过滤明显无关项目，再按新鲜度、主题、组织和 AI 项目配额组建候选池，最后让 AI 按一个**具体的读者画像**撰写：

> 企业 AI 落地、零售运营提效、知识库和自动化流程建设者，优先关注能迁移到真实业务的工具、产品思路和可复用方法。

选题引擎限制同一主题最多 2 个，并让一封邮件至少覆盖 6 个主题、通常 AI 项目最多 6 个。若严格主题避让后数量或主题数不达标，先允许近期主题回补；仍不足再把 AI 配额放宽到 9 个，最后才允许近期 owner 换推另一个未冷却项目，但一封邮件内同一组织仍只出现一次。候选足够时输出 12 个，极端候选不足时可降至 9—11 个或直接失败；项目 fullName 冷却和单封邮件同主题最多 2 个始终不放宽。AI 只负责对已经确定的项目写内容，不能临时换项目。

正文会先给出“本周观察”，再逐个说明项目是什么、对企业 AI／零售运营／知识库／自动化的迁移价值，以及建议的最小试用动作；内容只使用已选项目和候选事实，不补写未给出的功能或效果。

## 原理

```
GitHub Actions 每周日 18:07（北京时间）抓取 weekly/monthly 数据
    ↓
5 个语言维度去重合并 → 冷却与多样性筛选
    ↓
AI 只为已选项目写本周内容 → 发邮件到 QQ 邮箱
```

- 抓取、筛选和发送都在你的 GitHub Actions 中完成
- 你 Fork 后只用配置 DeepSeek + 邮箱
- Actions 定时调度可能延迟，18:07 不是秒级准点承诺
